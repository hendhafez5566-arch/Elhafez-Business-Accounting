## المطلوب تنفيذه كاملًا داخل الحزمة

1. **العميل والأسرة والمجموعة:** ملف العميل والمسافر، كشف فرد وكشف أسرة، مسؤول مالي قد لا يسافر، اختلاف المسافر عن المتعاقد والدافع، مرونة الدفع المباشر أو المندوب أو الخليط. بيانات الجواز قابلة للاستكمال بعد حجز مكان، مع النواقص والتكرار والتنبيه والصلاحيات. استخدم سجل الهوية الموحد ولا تكرر الأشخاص.
2. **البيع والحجز:** عمرة وخدمات منفردة، خدمات وأسعار واتفاقات لكل فرد، سعر البرنامج والخدمات الإضافية والخصومات، حجز مؤقت بمهلة وتنبيه وقرار موظف، نقل بين برامج مع أثر مالي موثق، إلغاء فرد أو خدمة أو الأسرة وفق الاتفاق والتكاليف. احفظ النسخ الأصلية والتعديلات. لا تعرض حجزًا نهائيًا دون سلطة فعلية على سعته.
3. **الدورة المالية الحقيقية:** فاتورة/استحقاق، قبض مؤكد أو انتظار تأكيد، قبض مباشر أو عن طريق مندوب، دفعة لعدة حجوزات مع اقتراح توزيع ومراجعة، زيادة رصيد، استرداد جزئي أو متعدد الدفعات، تسويات وإعفاء مع سبب وصلاحية. اعرض المطلوب والمدفوع والمتبقي لكل مسؤول مالي وفرد بدون جمع مزدوج. الإلغاء يعكس/يسوي ولا يمحو التاريخ. العملات وسعر الصرف والتقريب عبر أصحابها الحاليين.
4. **العمولات:** استخدم علاقات المندوب الرئيسي والتابع والاتفاقات التجارية الموجودة. ثبّت نسخة الاتفاق على الحجز، ونفّذ الاستحقاق المالي لدى expense-commission-recognition بتنسيق tourism-finance-orchestration، وليس داخل agent-management. ادعم نصيب الرئيسي/التابع والتغيير والإلغاء والتسوية، وعمولة الموظف عند انطباق الاتفاق دون ازدواج. حساب دقيق وتوزيع فرق التقريب محدد ومحفوظ. كشف العميل لا يكشف العمولة أو التكلفة الداخلية.
5. **واجهات كاملة قابلة للتعديل:** العميل/الأسرة والحجز والقبض والتوزيع والكشوف والتسوية وحالة المزامنة. لا تكتفِ API أو بيانات تجريبية. إعادة تصميم بنية الصفحة والأقسام والمكونات المحلية مسموحة؛ لا تفرض قالبًا بصريًا واحدًا. افصل الشكل عن الخدمات والقواعد المالية، مع RTL وA4 والصلاحيات وحالات الخطأ/الانتظار الواضحة.
6. **الأوفلاين:** أكمل تشغيل المكتب الفعلي عند قطع الإنترنت، والعمل المحدود على جهاز منفصل، والمزامنة والاستعادة وفق القرار الآتي. لا تعتبر Service Worker أو مسودات followup الحالية تشغيلًا كاملًا للنظام.

## قرار الأوفلاين المطلوب

- تشغيل المكتب داخل LAN: نفس API وأصحاب البيانات مع PostgreSQL وتخزين الملفات محليًا وواجهة متاحة محليًا، بدون تبعية وقت التشغيل لـCDN/خدمة سحابية إلزامية. اختبر بدءًا باردًا وتسجيل دخول محليًا بتفويض/استحقاق صالح ومحدد، وليس تجاوزًا للمصادقة عند انقطاع الشبكة. جهز وصف تشغيل محلي قابل للتكرار بأوامر واضحة وبيانات تجريبية مستقلة.
- سلطة كتابة واحدة للشركة افتراضيًا: لا تجعل المكتب والسحابة مصدرين ماليين مستقلين يحلان التضارب بآخر تعديل. وثّق نمط التشغيل المختار وطبقه. نقل السلطة يتطلب fencing ومنع كتابات السلطة السابقة؛ فقد heartbeat لا يسمح بترقية طرف آخر أثناء انقسام الشبكة. لا توسع إلى multi-master غير مثبت.
- الجهاز المنفصل: outbox مشفر دائم، معرف طلب ثابت، حالة pending/provisional ظاهرة، تفويض محدود للشركة/الفرع/المستخدم/الجهاز والمدة والعمليات. أعد التحقق من الصلاحية والفترة المالية وسعة الحجز عند المعالجة. عالج انتهاء التفويض وإلغاءه وتراجع الساعة بدون قبول صامت. صلاحية دون اتصال لا تلغي مخاطرة تأخر معرفة الإلغاء؛ وثّق حدودها.
- تأكيد نهائي دون اتصال مستقل يحتاج سلطة/حصة محجوزة لا يمكن صرفها مرتين؛ وإلا يظل الطلب معلقًا. لا تؤكد آخر مقعد لجهازين. لا تسقط تسجيل استلام نقدي فعلي إذا رفضت المزامنة؛ احفظه للمراجعة والعهدة والتسوية مع إيصال مؤقت صريح.
- المزامنة: هوية ثابتة وعملية اقتصادية ذرية لدى صاحبها، منع التكرار بعد ضياع الرد، ترتيب الاعتمادات، استئناف وانقطاع متكرر، تعارض قابل للمراجعة، ترقيم مؤقت ثم رسمي دون إعادة استخدام رقم نهائي. لا تدمج أرصدة بحسابات العميل.
- النسخ والاستعادة: قاعدة البيانات والملفات والمرفقات وبصماتها والطلبات المعلقة والإيصالات/checkpoints وحالة الأجهزة وسياسة استعادة المفاتيح. جرّب الاستعادة إلى بيئة نظيفة ولا تُعد تنفيذ عمليات سبق اعتمادها. حافظ على عزل الشركات والفروع.

صاحب التنسيق الجديد المخطط `offline-coordination` موثق في routing/architecture ومسموح تنفيذه من القالب إذا احتاجت البيانات الدائمة ذلك. لا يملك أموالًا أو حجوزات أو سعة؛ لا تُنشئ دفتر حسابات موازيًا داخله. platform-core يملك الهوية والصلاحيات، document-numbering الترقيم، platform-operations تشغيل النسخ، data-exchange تبادل البيانات، وأصحاب الخدمات يملكون اعتماد الأثر.

## طريقة التنفيذ والحوكمة

قبل البرمجة افحص المسارات الموجودة واكتب خريطة مالك/عقد/تغيير/اختبار. حدّث manifest الجديد `.changes/core-workflow-offline.json` نفسه بنطاق الملفات الحقيقي تدريجيًا؛ لا تنشئ manifest ثانيًا ولا تعدل manifest الأساس الموروث. أي ملف محمي لازم للتكليف يُصرّح به بسبب محدد. التوسيع الضروري داخل هذه الحزمة مصرح، وليس إذنًا لتغيير أقسام لا علاقة لها.

لا تضع كل المنطق في صفحات أو controller واحد. لا وصول مباشر لجداول مالك آخر، لا تدوير dependencies، لا تعديل migrations تاريخية، لا float للأموال، ولا إضعاف اختبارات/guards أو إضافة مسارات تجاوز. احفظ APIs العامة؛ migrations جديدة وقابلة للاختبار على قاعدة جديدة وترقية قاعدة ذات بيانات. استعمل العقود والأحداث/versioning الحالية وtransactional outbox عند الحاجة بدل تأكيد جزئي صامت بين المالكين.

الموجود بالفعل: followup encrypted drafts/queue/manual retry/backup، public offline shell، سياق اختيار محدود، durable server retries، hierarchy واتفاقات نسبة عمولة تجارية مؤرخة. حافظ عليها وادمجها حيث يلزم؛ لم تكن عمولات مالية مكتملة أو offline ERP.
