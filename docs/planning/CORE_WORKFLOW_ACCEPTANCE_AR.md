15 أكتوبر 2026. الفرع `codex/core-workflow-offline`؛ أساس PR المطلوب `development/flexible-section-ui@9ac403dc7b6fa50669571577f1b11eb6194843f0`. هذا تقرير عمل جديد، وليس إعادة استخدام CI 1986 أو شهادة اكتمال الحزمة/ERP. مصفوفة البنود الـ296 في CORE_WORKFLOW_REQUIREMENTS_MATRIX_AR.md، وخريطة المالك/العقد/التغيير/الاختبار في CORE_WORKFLOW_OWNER_MAP.md.

## التنفيذ الحالي

- الحجز يفصل العميل المتعاقد عن العميل المسؤول ماليًا، الذي لا يدخل ضمن عدد المسافرين. يمكن ربط مسافرين ذوي ملفات مستقلة دون فرض أن الجميع ملف عميل واحد. `familyReference` يجمع الحجوزات للعرض، ولا ينشئ دفتر ذمم. حقول قديمة بلا مسؤول مستقل تستخدم المتعاقد كما كانت.
- يمر المسؤول المالي وحده إلى فاتورة TFO/Billing. كشف الأسرة يجمع الفاتورة مرة واحدة وبعملة مستقلة. الحجز متعدد المسافرين يبقى SHARED_NOT_DISTRIBUTED؛ لا يُختلق سداد لكل فرد. رقم «المسوّى» هو الإجمالي ناقص المتبقي ويشمل التسويات، وليس مجموع النقد وحده. مطبوعة العميل إسقاط مستقل يهرب النصوص ولا ينسخ شاشة الإدارة أو العمولة/التكلفة.
- إنشاء الحجز ذو requestId ثابت يتحمل ضياع الرد وإعادة الإنشاء. المرجع مشتق إلى هوية تقبلها طبقة التدقيق UUID. تسجيل مراجع العميل والمندوب يستعمل إدخالًا ذريًا متجاهلًا للتكرار نفسه، دون إعادة إنشاء العلاقات في سباق upsert. حفظ انتقالات الحجز يستخدم revision ويحتفظ بالتاريخ داخل المعاملة.
- اتفاق الرئيسي/التابع يثبت على الحجز قبل التأكيد. ECR يملك سياسة التوزيع الدقيقة: الرئيسي إلى الأسفل على أصغر وحدة للعملة، والتابع يأخذ الباقي؛ دقة العملة تُقرأ من currency-fx. مثال مستقل: 100.01 × 33.333333% ينتج 33.33 و66.68. يثبت TFO خطة التوزيع ويستأنف المطالبات بهويات ومصادر مستقلة لكل نصيب. فحوص الإلغاء/العكس تشمل جميع المطالبات. الاستحقاق المحاسبي لا يُنشأ داخل agent-management؛ اعتماد ECR الحالي يرحّل القيود، مع حفظ نطاق الفرع.
- مالك `offline-coordination` منشأ من القالب، ومسجل في AppModule، ويملك بيانات التنسيق فقط. يدعم BOOKING_CREATE وBOOKING_CONFIRM وBOOKING_DEPOSIT. الطلب ثابت الهوية والبيانات، مع اعتماديات وإيصال وحالة ومعالجة ذات lease؛ إعادة المحاولة تستخدم مفتاح المالك نفسه. لا تتحول نتيجة غير مؤكدة إلى نجاح.
- التفويض مسجل للخادم بنطاق الشركة/الفرع/المستخدم/الجهاز والعمليات، بحد أقصى ثماني ساعات. واجهة الحجز تستخدم أربع ساعات. يتحقق الخادم من النسخة المخزنة، لا من نسخة الجهاز، ومن الصلاحيات الحالية عند المزامنة. التفويض المنتهي/الملغى يحول الطلب الوارد إلى REVIEW؛ إثبات النقد لا يضيع ولا يعد قبضًا معتمدًا. إذا تعطلت هوية المستخدم قبل الإرسال يبقى الطلب المشفر على الجهاز ولا يتجاوز المصادقة.
- سجل الجهاز IndexedDB مشفر AES-GCM بمفتاح PBKDF2 وبربط نطاق السجل كبيانات مصادق عليها. يثبت الهوية والتوقيت ويحمي تحديث السجل من سباق التبويبات بواسطة revision. يرفض الحجز الجديد بعد انتهاء التفويض أو تراجع الساعة. يسمح بحفظ ملاحظة استلام نقدي منتهية التفويض للمراجعة فقط. استيراد نسخة لا يحذف الموجود، ولا يثق بنتيجة قبول قديمة قبل إعادة التحقق من الخادم بنفس الهوية.
- سلطة الكتابة تُسجل للشركة مرة واحدة. HTTP guard يمنع الكتابات الاقتصادية من خادم بهوية مختلفة أو بلا هوية بعد التسجيل. لا توجد عملية ترقية تلقائية أو نقل سلطة عبر heartbeat. إعداد مكتب جديد يتطلب ELHAFEZ_WRITE_AUTHORITY_ID وتسجيلها بصلاحية platform.configuration.manage عبر POST /offline/authority/enroll. نقل خادم فعلي أو استعادة نسخة كتابة يتطلب إيقاف/حجب السابق أولًا؛ نسخ هوية الخادم عمدًا إلى مثيل مستقل ليس fencing ولا يصرح به هذا التنفيذ. أي worker اقتصادي مستقبلي يجب أن يستخدم الفحص العام نفسه، لا أن يعتمد على HTTP guard.
- أصلح قبول PostgreSQL عيبًا في مالك الخزينة: سند القبض كان يمرر حقول الأمر غير المخزنة إلى Prisma. التعيين أصبح صريحًا ومطبوع النوع في reserve/save، دون تغيير ملكية الحسابات.

## التشغيل المحلي

`deploy/local/start.sh` يبدأ API وواجهة الإنتاج من نفس المالكين والقاعدة المحلية، ويفحص الصحة، ويوقف عملياته هو فقط. لا يحمل اعتماديات وقت التشغيل من CDN. تثبت المتطلبات وبناء الويب ومحركات Prisma وصورة المكتب أثناء الاتصال أولًا. الصورة المحلية تحتاج OpenSSL 3؛ الصورة Node slim وحدها فشلت في اكتشاف محرك Prisma المناسب، ولذلك أُضيف Dockerfile تحضير محدود يعتمد الحزم الموقعة وصورة أصل مثبتة بالبصمة. CA الجلسة يُمرر كـbuild secret ولا ينسخ إلى الصورة.

أوامر التجربة الآمنة في tools/experiments/core-workflow/README.md. تشغيل HTTP المحلي المرفق للتطوير/الفحص؛ أجهزة LAN الإنتاجية تحتاج TLS موثوقًا محليًا لكي تعمل WebCrypto وService Worker، باستخدام عقد Nginx الموجود في deploy. لا تدعِ أن اختبار HTTP على loopback يثبت تثبيت شهادات كل أجهزة الشركة.

تبقى مفاتيح MFA الحالية وبيانات اتصال القاعدة ومجلد الملفات في إعدادات آمنة خارج المستودع. تصدير سجل الجهاز لا يتضمن عبارة فك القفل. فقد العبارة يفقد القدرة على فك النسخة؛ لا يوجد مسح عن بعد فوري أو استرجاع سحري للمفتاح. لا تمدد الجلسة أو الترخيص عند انقطاع الإنترنت؛ الاشتراك المحلي الصالح وحدوده الحالية يبقيان نافذين.

## المتبقي المطلوب قبل إغلاق التكليف

الحزمة **غير مكتملة**، ولا يجوز اعتبار هذا checkpoint قبولًا نهائيًا لها:

1. توزيع مالي صريح لكل فرد وعدة مسؤولين داخل الحجز الواحد؛ كشف الفرد المستقل وتخصيص دفعة على عدة حجوزات مع الاقتراح والمراجعة من UI. الموجود يثبت مسؤولًا واحدًا للحجز وكشفًا مشتركًا فقط.
2. مهلة حجز مؤقت تستهلك سعة فعلية وتُنبه دون تحرير آلي، ونقل البرامج مع الأثر المالي الكامل، وإلغاء فرد/خدمة وتسويات واستردادات جزئية متعددة بعملة مختلفة في رحلة browser مترابطة.
3. عمولة الموظف وربط شروط توقيت الاستحقاق/تغيير المندوب/تسوية العمولة بكامل دورة الحجز؛ الموجود تقسيم رئيسي/تابع ومالكو الاعتماد/السداد الحاليون.
4. مسار مراجعة تشغيلية لحسم REVIEW مع السبب وإسناد النقد عند تعطيل المستخدم أو جهازه. لا زر يتجاوز الرفض أو يحذف الطلب. إعادة المراجعة بتفويض حديث لم تُنفذ كدورة مكتملة.
5. فتح جهاز منفصل بعد فقد الجلسة/إعادة تشغيل المتصفح الكامل دون خادم، ومزامنة المرفقات الكبيرة واستئنافها. الغلاف والطابور الحاليان لا يثبتان تسجيل دخول مستقل بلا سلطة محلية.
6. قبول جهازين فعليين وآخر مقعد، وإغلاق فترة أثناء المزامنة، واختبار الترقيم المؤقت إلى الرسمي دون حرق رقم عند ضياع الرد. لا توجد حصص سعة مستقلة؛ كل طلب جهاز مؤقت حتى اعتماد المالك.
7. استعادة إنتاجية متماسكة تشمل كل المرفقات ومفاتيحها وطوابير الأجهزة/checkpoints وإعادة التحقق على بيئة نظيفة، واختبار ترقية أرشيف مالي تشغيلي متنوع. ترقية حجز قديم نجحت، لكن تجربة القاعدة النظيفة والاستعادة المحدودة لا تغطي كل ذلك.
8. مزيد من screenshots للعميل والحساب والإلغاء والأخطاء والانتظار المالي، ومراجعة A4 وشهادات LAN والأجهزة المستهدفة. لا تكفي صور الحجز والمزامنة وحدها.

لا استضافة مالية ثانية ولا مزامنة cloud/office multi-master. لا الحج الكامل أو HR أو واتساب إنتاجي أو OCR في هذه الحزمة. صلاحية الأوفلاين لا تلغي خطر تأخر معرفة إلغاء التفويض. لا دمج ولا نشر. PR المطلوب مسودة فقط، ووصول GitHub API المحجوب في البيئة يبقى عائقًا خارجيًا إذا لم تُطبق إضافة api.github.com المحفوظة.
