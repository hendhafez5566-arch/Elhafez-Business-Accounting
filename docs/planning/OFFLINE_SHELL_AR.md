# فتح الواجهة بعد انقطاع الإنترنت

## السلوك

بناء الويب ينتج Service Worker ونسخة عامة متماسكة من HTML وملفات JavaScript وCSS ذات الأسماء المرتبطة بمحتواها. بعد زيارة ناجحة وتثبيت النسخة، يمكن فتح رابط داخلي للواجهة بعد غلق المتصفح وغياب الخادم. HTML المحفوظ مضمن في العامل نفسه، فلا يختلط HTML من نشر أحدث بملفات نشر أقدم أثناء التثبيت.

الشاشة تعرض تنبيهًا عند انقطاع اتصال المتصفح. هذه الإشارة ليست اختبار صحة الخادم. لا تخزن الطبقة ردود API أو بيانات الدخول أو حسابات العملاء أو صفحات Owner؛ لا تعيد إرسال أي كتابة. طلبات API وOwner والصحة تُترك للشبكة، بما فيها حالة التنقل. التحميل العادي للصفحات يفضل الشبكة، وعند تعذرها فقط يستخدم HTML العام المحفوظ.

تحديث العامل لا يستبدل كود التبويبات المفتوحة أثناء عملية. ينتظر غلقها؛ بعد تفعيله تُحذف نسخ الواجهة القديمة فقط. فشل تثبيت بديل لا يحذف النسخة السابقة. العامل نفسه يقدم بـ no-store في المعاينة والـstatic proxy، بينما تظل ملفات البناء ذات الأسماء المتغيرة قابلة للتخزين طويلًا.

لا تغيير في API أو Prisma أو مالية النظام أو صلاحياته. لا يستدعي هذا البناء خدمة خارجية جديدة ولا ينشر النظام. التغيير في عرض الويب وبنائه وتسليم ملفاته العامة، مع بقاء أصحاب البيانات الحاليين.

## الأدلة

نجحت 8 حالات Chromium (9 باحتساب الأب) على ملف بناء الإنتاج وتحت Content-Security-Policy الحالية: التثبيت، إعادة تشغيل عملية المتصفح مع غياب الخادم وفتح رابط داخلي، عدم اختلاق جلسة عند محاولة الدخول أوفلاين، استبعاد API وOwner والصحة، عدم تخزين الردود ذات البيانات، انتظار التحديث للتبويبات، رفض بديل ناقص مع بقاء القديم، وفشل الزيارة الأولى غير المجهزة دون اتصال.

اختبارات الواجهة 99 واختبارات الـproxy السابقة 2 نجحت، واختبارا تقديم العامل من خادم المعاينة والـproxy أكدا no-store للعامل وHTML والتخزين الطويل للملفات ذات البصمة. فحوص الأنواع وlint والبناء والمعمارية وسلامة نطاق التغيير تُشغّل على هذا التغيير. نتيجة GitHub الحالية في PR #146؛ اختبارات Chromium منفذة محليًا وليست مضافة خفية إلى CI.

## المتبقي

هذه إتاحة ملفات الواجهة فقط. بعد إعادة التشغيل الكامل تظهر شاشة الدخول إذا لم توجد جلسة صالحة؛ الدخول يحتاج الخادم. لا جلسات أو صلاحيات أوفلاين جديدة، ولا تحميل بيانات العمل المرجعية دون اتصال، ولا مزامنة تلقائية. استرجاع طابور المتابعات بعد بدء جلسة صالحة يظل المسار السابق.

يلزم HTTPS أو localhost ودعم Service Worker وتثبيت ناجح سابق. مسح بيانات الموقع أو إخلاء تخزين المتصفح قد يزيل النسخة. تحديث عبر عدة تبويبات يعني غلق التبويبات القديمة ثم فتح النظام مجددًا. لم يُنجز في هذا التغيير دخول أوفلاين أو تشغيل الحسابات دون إنترنت أو سياسة استعادة مفاتيح الطابور أو اعتماد جاهزية للبيع.
