# قائمة طلبات المتابعة المحلية — 2026-10-15

## السلوك الحالي

أصبحت شاشة المتابعات تحفظ عدة طلبات مستقلة، بدل الاكتفاء بخانة طلب واحدة.
زر «حفظ طلب بالقائمة دون إرسال» يحفظ البيانات وهوية الطلب مشفرين ويعلن النجاح
بعد اكتمال معاملة التخزين. زر «بدء متابعة أخرى مع الاحتفاظ بالمحفوظة» يفك
اختيار النموذج فقط، ويتيح إدخال طلب جديد دون حذف المعلّق أو المؤكد السابق.

القائمة تعرض العميل والمسؤول والموعد والإجراء وحالة النتيجة، مع اختيار طلب
واسترجاعه أو إعادة إرساله وحده. تُخفى الطلبات المؤكدة افتراضيًا مع خيار عرضها،
وتظهر أعداد الطلبات المحملة والمنتظرة والمؤكدة. لا تدعي الأعداد أنها قائمة
الخادم أو كل الأجهزة. إن لم تتحمل أسماء المراجع، يظهر وصف للبيانات الناقصة
بدل عرض المعرف الداخلي كاسم عميل أو موظف.

الطلب المرفوض أو مجهول النتيجة يبقى محفوظًا بهويته، لكنه لم يعد يمنع حفظ
طلب آخر أو إرسال صف آخر. الإعادة تستخدم البيانات الأصلية؛ تعديل نموذج طلب
مختار لا يغيّر بياناته ولا ينشئ طلبًا بديلًا خفية. تبدأ متابعة أخرى صراحة
عند الرغبة في بيانات مختلفة. لا إرسال جماعي أو تلقائي عند عودة الشبكة.

## سلامة التخزين والتبويبات

قاعدة IndexedDB انتقلت إلى الإصدار 2، بنفس مخزن المسودات المشفرة مع مفاتيح
مستقلة لكل طلب، ومخزن اختيار يحفظ مراجع مبهمة فقط. بيانات العميل والموعد
والإجراء والنتيجة تظل داخل AES-GCM. عند تكوين قائمة موجودة تُراجع عبارة
الحماية قبل إضافة طلب جديد، لمنع إنشاء عناصر بعبارة خاطئة داخل نفس القائمة.
المسودة العادية ما زالت مستقلة عن طلبات الإرسال.

ترحيل سجل الإصدار 1 يفك تشفيره ويعيد تشفيره بمفتاح موضعه الجديد، ثم يحفظ
العنصر واختياره ويحذف السجل القديم داخل معاملة واحدة فقط. يحتفظ بنفس
requestId وpayload والتأكيد إن وجد. وقت إضافته للقائمة الجديدة ليس دليلًا على
موعد إنشاء طلبه الأصلي. فشل الترحيل يحتفظ بالسجل الأصلي. إصدار التطبيق القديم
الذي يطلب قاعدة الإصدار 1 يتلقى VersionError بعد الترقية، فلا يستطيع إنشاء
طلب قديم موازٍ عبر مسار حفظه السابق.

إنشاء الطلب وتغيير اختيار القائمة ذريان؛ اختيار أحدث في تبويب آخر لا يغيّر
الطلب المثبت في نموذج سبق حفظه. قبول الخادم يحدث سجل ذلك الطلب نفسه، ولا
يعدل صفًا آخر أو يحذف الطلبات المؤكدة. «بدء متابعة جديدة بعد التأكيد» أصبح
يحرر الاختيار مع الاحتفاظ بالسجل المؤكد في القائمة، بدل إزالة السجل المحلي.

لا تغيير في API أو Prisma أو المهاجرات أو أصحاب البيانات أو الحسابات. ما زال
crm-followups يملك الحقيقة النهائية؛ القائمة حالة محلية للإرسال وليست جدول
متابعات بديلًا عن الخادم. التغيير محصور في عرض الويب وتخزينه وأدلته.

## الأدلة المنفّذة

نجحت **15 حالة Chromium جديدة** (16 مع الاختبار الأب):

1. عبارة قديمة خاطئة لا تحذف السجل ولا ترسل.
2. فشل الكتابة أثناء الترحيل يحفظ البايتات الأصلية.
3. تبويبان يرحلان هوية قديمة واحدة مع بقاء المسودة العادية.
4. إصدار التطبيق القديم لا يستطيع فتح الإصدار الأحدث من التخزين.
5. حفظ عدة طلبات أوفلاين مع بقاء القديم المعلّق.
6. استرجاع المجموعة بعد غلق عملية المتصفح، ثم إضافة طلب بدون إنترنت.
7. تثبيت اختيار الطلب ورفض استبدال بياناته بتعديل النموذج.
8. رفض صف لا يمنع تأكيد صف آخر، مع بقاء تاريخ المؤكد.
9. قطع رد صف ثم إعادته لا يغير باقي الصفوف أو يكرر الأثر.
10. العبارة الخاطئة تخفي القائمة ولا تضيف عناصر بعبارة أخرى.
11. عزل المستخدم والشركة والفرع.
12. تبويبان يعيدان صفًا واحدًا بأثر واحد.
13. الحفظ المتزامن لنفس الاختيار يتفق على هوية واحدة.
14. تغيير اختيار القائمة في تبويب لا يعيد توجيه نموذج التبويب الآخر.
15. السجل القديم المؤكد يحتفظ بتأكيده ولا يعاد إرساله عند الترحيل.

اختبارات الإرسال السابقة **13 حالة** والمسودة السابقة **9 حالات** أُعيدت
كما هي ونجحت؛ إجمالي 37 حالة متصفح في الأجنحة الثلاثة. اختبارات الواجهة
99/99، وفحص أنواع الويب وlint والبناء والمعمارية شُغّلت بنجاح محليًا.
الفحوص المركزية وPostgreSQL وقبول HTTP الحقيقي يعاد تشغيلها في جودة PR #146؛
مرجع النتيجة الحالية هو فحص ذلك الطلب.

## حدود الدليل والخطوة اللاحقة

سيرفر HTTP في اختبارات المتصفح fixture بذاكرة قبول؛ لا نستبدل وصفه بدليل
التطبيق الحقيقي. قبول AppModule والجلسات وRBAC وPostgreSQL موثق بصورة منفصلة
في FOLLOWUP_REAL_HTTP_ACCEPTANCE_AR.md. لا تزال جلسة متصفح متصلة بذلك التطبيق
كاختبار واحد، وإقلاع الواجهة من الصفر دون إنترنت، وإدارة مفاتيح قابلة للاسترجاع
وحل الرفض النهائي ومزامنة باقي أنواع العمليات خارج هذا العمل.

القائمة خاصة بهذا المتصفح، ومراجعة نتيجة جهاز آخر تحتاج الخادم. حذف بيانات
المتصفح أو فقد العبارة ليس له استرجاع هنا. عرض القائمة يفك تشفير عناصرها؛ لم
نقِس أداء آلاف العناصر أو ننجز صفحات تحميل ومؤشرات بحث لطوابير ضخمة. لا يدعي
هذا التغيير اكتمال Offline النظام كله أو قابليته للنشر التجاري. الفرع لم يدمج
في main، ولا نشر ضمن هذا العمل.
