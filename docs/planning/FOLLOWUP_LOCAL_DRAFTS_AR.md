# مسودة متابعة عميل محفوظة على الجهاز — 2026-10-15

## المنفذ

أضيفت إلى شاشة المتابعات الحالية أزرار حفظ واسترجاع وحذف مسودة محلية.
الحفظ يدوي لمسودة واحدة لكل شركة وفرع ومستخدم في المتصفح الحالي، ويستبدل
المسودة السابقة صراحة. تشمل بيانات العميل المحتمل والمسؤول ونوع التواصل
والموعد والإجراء التالي؛ لا تشمل مرفقات أو معاملات مالية.

المسودة مشفرة بـ AES-GCM مع مفتاح مشتق من عبارة حماية لا تقل عن 12 حرفًا
بـ PBKDF2 / SHA-256 و150000 دورة، وملح وIV عشوائيين لكل حفظ. لا تحفظ عبارة
الحماية أو المفتاح. هوية الشركة والفرع والمستخدم مرتبطة بالتشفير AAD.
الحفظ لا يعلن النجاح قبل اكتمال معاملة IndexedDB. الاسترجاع يراجع بنية
البيانات ولا يغير النموذج عند فشل فك التشفير.

يجب وجود جلسة محلية غير منتهية، وفرع نشط تابع للشركة واشتراك مسموح بالتشغيل.
تغيير الجلسة يعيد إنشاء شاشة المتابعات، فيمسح النموذج وعبارة الحماية والنتائج
السابقة. هذه حماية محلية للعرض وليست بديلًا عن تفويض الخادم؛ إلغاء الصلاحية
عن بعد أثناء انقطاع الشبكة لا يمكن معرفته محليًا فورًا.

## الملكية والتأثير

الملفات داخل تطبيق الويب وتملك حالة عرض مؤقتة فقط. `crm-followups` يظل المالك
الوحيد لجدولة المتابعة الحقيقية عبر API الحالي. لا تغيير في API أو مخطط
Prisma أو المهاجرات أو الحسابات أو جداول الأعمال. المسودة لا تُرسل تلقائيًا،
ولا تعد متابعة مجدولة، وتظل محفوظة حتى حذفها أو استبدالها يدويًا. لا تستخدم
المسودة كإثبات لنجاح جدولة؛ قبل أي إعادة إرسال بعد استجابة ملتبسة راجع السجل.

## التحقق

اختبار Chromium يجمع ويعرض مكوّن `FollowupsPage` الإنتاجي نفسه مع مراجع
وجلسة اختبارية، وليس واجهة بديلة. نجحت تسعة سيناريوهات:

1. حفظ من النموذج الحقيقي أثناء انقطاع الإنترنت بدون إرسال جدولة.
2. عدم وجود الملاحظة أو عبارة الحماية نصًا صريحًا في السجل المحفوظ.
3. إغلاق عملية المتصفح وفتح نفس ملفه الشخصي ثم استرجاع النموذج بعد فصل الشبكة.
4. رفض عبارة خاطئة مع الحفاظ على النموذج الجاري.
5. تغيير المستخدم يمسح النموذج وعبارة الحماية ويعزل المسودات.
6. رفض حفظ بجلسة منتهية.
7. عزل نفس المستخدم بين شركتين وفرعين.
8. فشل كتابة محاكى على IndexedDB يظهر الفشل ويحافظ على المسودة السابقة.
9. استرجاع المستخدم الأصلي لمسودته ثم حذفها صراحة.

عداد Node يعرض 10 اختبارات ناجحة لأنه يحتسب الاختبار الأب أيضًا.
اختبارات الويب الحالية 99/99، وبناء المتصفح وفحص الأنواع وlint وفحص المعمارية
تم تشغيلها. تفاصيل فحوص الحوكمة تسجل مع تسليم التغيير.

## الحدود والخطوة التالية

لا يشمل هذا التغيير فتح النظام من الصفر بدون إنترنت: بعد إعادة تشغيل
المتصفح حُمّلت الشاشة بالاتصال أولًا ثم فُصلت الشبكة للاسترجاع. لا كاش محلي
لأسماء العملاء والموظفين؛ عند انقطاع الاتصال قبل تحميل المراجع قد لا يمكن
اختيار أسماء جديدة. المسودة ليست نسخة احتياطية؛ حذف بيانات المتصفح أو نسيان
العبارة يفقد الوصول إليها. لا توجد مزامنة أو نسخ استرجاع أو تسوية تعارض
تبويبين أو مراجعة أمنية شاملة. التشفير لا يحمي من كود خبيث يعمل داخل الجلسة.

التالي هو توفير قبول موثق مانع لتكرار طلب الجدولة في مالكه الفعلي، واختباره
على PostgreSQL والصلاحيات الحقيقية، قبل إضافة إرسال أو إعادة محاولة تلقائية.
