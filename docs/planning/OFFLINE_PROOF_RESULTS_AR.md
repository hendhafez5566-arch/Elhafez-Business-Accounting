# نتيجة تجربة الأوفلاين المعزولة

15 أكتوبر 2026 — الحالة: **نجاح إثبات آليات محددة في متصفح فعلي، وليس اكتمال أوفلاين النظام**.

## البيئة والتنفيذ

- Node.js 24.19.0، وPlaywright 1.62.1، وChromium 153.0.8010.0.
- تخزين IndexedDB فعلي، وService Worker فعلي، وتشفير AES-GCM ومفتاح مشتق بـPBKDF2.
- جهازان تجريبيان ممثلان بملفي متصفح مستقلين، وخادم معمل محلي بقاعدة SQLite على القرص.
- تعذر تنزيل المتصفح من قناة Playwright المعتادة في هذه البيئة؛ استُخدم Chromium من حزمة `@sparticuz/chromium` 153.0.0، عبر مسار تنفيذي صريح. لم يُستبدل المتصفح بمحاكاة.
- الكود في `tools/experiments/offline-proof`، ولا يستورده التطبيق ولا ينشئ حسابات أو حجوزات حقيقية.

## النتائج: 16 سيناريو ناجحًا

| السيناريو | النتيجة |
|---|---|
| حفظ طلب ومرفق بدون اتصال | PENDING محفوظ، ولا أثر على الخادم |
| فحص البيانات الخام على الجهاز | محتوى الطلب والمرفق غير ظاهرين كنص واضح |
| إغلاق عملية المتصفح وإعادة تشغيله دون شبكة | فتح الغلاف المخزن واستعادة الطلب والمرفق بعد فك القفل |
| عودة الاتصال وإعادة المزامنة | أثر واحد فقط لنفس الطلب |
| انقطاع الرد بعد حفظ الخادم | إعادة المحاولة لا تكرر الأثر |
| فشل بعد الكتابة وقبل COMMIT | تراجع معاملة SQLite، والطلب يبقى قابلًا للمحاولة |
| فشل حفظ محلي | إلغاء معاملة IndexedDB وإظهار فشل؛ لا إعلان نجاح ولا سجل مقبول وهمي |
| إرسال نفس معرف العملية بمحتوى مختلف | رفض صريح بدل دمج أو تكرار |
| جهازان منفصلان يطلبان آخر مكان تجريبي | تأكيد واحد وانتظار واحد، والرصيد لا يصبح سالبًا |
| تعديل نفس السجل من نسختين قديمتين | تعارض إصدار، دون سحق تعديل الجهاز الأول |
| تبديل نطاق شركة/مستخدم/جهاز | لا تظهر قائمة طلبات النطاق السابق |
| انتحال شركة أو فرع في الطلب | الخادم يرفض النطاق وفق هوية المعمل |
| انتهاء تفويض التجربة المحلي | منع إنشاء طلب جديد |
| إعادة تشغيل الخادم | بقاء سجل عدم التكرار ونتيجة السعة على القرص |
| سحب إذن مستخدم قبل المزامنة | الطلب يبقى ظاهرًا للمراجعة، ولا أثر مقبول على الخادم |
| سر فك قفل خاطئ أو تعديل النص المشفر | فشل فك التشفير، وليس قبول بيانات تالفة |

ملاحظة العد: السيناريو الأول يشمل الحفظ وفحص النص الخام، والسيناريو الأخير يجمع حالتي فك القفل والتلاعب. ملفات الاختبار الفعلية تحتوي 16 اختبارًا فرعيًا تحت اختبار جامع؛ Node يطبع **17 PASS / 0 FAIL**. جدول العرض يجمع ويفصل بعض النتائج لسهولة القراءة؛ العدد المرجعي هو أسماء الاختبارات الفرعية في الملف.

## ما الذي نحتفظ به من التجربة؟

القرار المناسب هو استخدام سجل أوامر ثابت الهوية وطابور دائم مع حالات ظاهرة، ومراجعة الإصدارات والصلاحيات والسعة عند القبول؛ وليس نسخ حالة الجهاز بالكامل فوق الخادم. آليات الحفظ المشفر وإعادة الإرسال ممكنة في متصفح فعلي.

## ما لم يُثبت بعد؟

- هذه ليست تجربة ترحيل قيد مالي أو تحصيل حقيقي أو فتح فترة أو حجز من مخزون النظام؛ الربط بمالكي الحسابات والمخزون مرحلة لاحقة.
- هوية المعمل ومدة التفويض ثوابت اختبار؛ لا تحل محل مصادقة وتفويض إنتاجي موقعين ومراجعة مفاتيح وتشفير.
- لم تُختبر مزامنة PostgreSQL أو تعدد عمليات الخادم أو مزامنة الاستضافة مع مكتب أوفلاين.
- لم تُختبر أرقام فواتير رسمية أو استئناف مرفقات ضخمة أو استعادة الطابور من نسخة احتياطية أو امتلاء مساحة الجهاز أو سباق تبويبات.
- لم يُختبر التطبيق على Android أو iOS أو سياسات حذف المتصفح للتخزين.
- التجربة تُشغّل صراحة من دليلها؛ نجاح CI العادي ليس دليلًا على إعادة تشغيل المتصفح في كل PR.

## الخطوة التالية المحددة

تعريف مالك سجل الأوامر وتفويض الأجهزة في خريطة المعمارية، ثم دمج مسار غير مالي واحد عبر API العام للمالك الحالي، واختباره على PostgreSQL. بعده طلب مالي مقيد يمر بالخدمة المحاسبية الحالية مع تحقق الفترة والرصيد وعدم التكرار؛ لا تُنشأ نواة مالية على الجهاز كحل موازٍ. يبقى نموذج خادم المكتب الواحد مقابل الأجهزة المستقلة قرارًا يحتاج تجربة نشر منفصلة.
